# v1.10.0 — CJK fix, 13 languages, agent-worded holding line, mTLS

## Fixed

- **Chinese, Japanese and Korean replies now reach Assist** (#22). With **Strip emojis** on (the default), the emoji filter also removed every CJK character, so the whole reply was erased and Assist showed "..." with nothing spoken. If you use OpenClaw in one of these languages, update for this alone.
- **Follow-up questions in Chinese, Japanese and Arabic keep the mic open**, and emoji stripping now catches newer emoji it used to miss.
- **You can clear the gateway token and model override** under **Configure** (#26).
- **Changing only the session no longer reloads the integration** (#28).

## New

- **The holding line is the agent's own words.** When a request takes a while, you used to hear the same "On it — I'll let you know when it's done." every time. Now, if the agent says "Let me go through your inbox." and then works for a while, the turn ends on that sentence, and the rest of the answer is announced when it's ready. This also ends the long silent waits after a first sentence. Tip: ask your voice agent to say briefly what it's about to do before using a tool.
- **Thirteen languages.** The settings screens are translated into German, French, Spanish, Italian, Dutch, Polish, Brazilian Portuguese, Swedish, Japanese, Korean, and Simplified and Traditional Chinese. The integration's own spoken phrases (the holding phrase, and the messages for a timeout or connection problem) are spoken in the language of each request.
- **Client certificates (mTLS)** (#27). If your gateway sits behind a proxy that requires a client certificate, set **Client certificate path** and **Client private key path** during setup or under **Configure**. See "Client certificates (mTLS)" in the README.

## Behaviour changes

- A reply that starts and then goes quiet for the **Grace period** is now finished in the background and announced, instead of keeping the satellite waiting.
- A deferred turn never reopens the mic, even if its holding line is a question.
- The default holding phrase is now spoken in the request's language. A holding phrase you typed yourself is still used exactly as written.

## Upgrade

Update through HACS, then **restart Home Assistant**. No configuration changes are needed.

## A note on the translations

They are machine-generated and have not been reviewed by native speakers. Corrections are very welcome: each language is one file in `custom_components/openclaw/translations/`, and the spoken phrases are in `custom_components/openclaw/phrases.py`.
